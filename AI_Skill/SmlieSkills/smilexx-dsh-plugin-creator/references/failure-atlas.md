# DSH 插件故障定位

先确定插件形态与失败边界，再修改代码。动态流程见[动态插件开发](cordis-dynamic.md)，插件包流程见[插件包开发](package-development.md)。

## 数据契约与业务范围

| 症状 | 优先检查 | 修正方向 |
| --- | --- | --- |
| 大 JSON 被截断 | 标准值、模型文本、界面元数据或嵌套事件中哪一层超限 | 给对应展示层设置边界，必要时增加高层聚合工具，再考虑存储策略 |
| HTTP 200 但工具结果被拒绝 | 实际响应与 `output.schema` 的必填、可空字段 | 用脱敏响应校验真实结构，不从旧类型猜契约 |
| Agent 反复翻页、上下文过大 | 原子列表是否承担了复杂查询规划 | 保留有界原子接口，增加负责分页、关联、聚合与缺口说明的业务工具 |
| 故障被显示为空结果 | 回退是否捕获所有异常 | 仅在明确兼容信号触发回退，传播鉴权、输入及服务错误 |
| 真实租户数据为空 | 插件是否加入产品数据不拥有的额外范围维度 | 对照服务实现、只读部署响应和产品归属修正过滤 |
| 为复用凭据而调用 CLI | 认证存储与传输方式是否被混同 | 合理复用凭据，用受支持的类型化 API 执行业务 |
| 测试配置隐藏生产数据 | 基础 URL 覆盖是否同时改变发现与数据请求 | 明确环境身份，隔离测试配置 |
| 内部对象序列化失败或日志暴涨 | 是否整体复制 Service、会话快照、工具状态 | 只提取必需叶子值，再构造有界自有 JSON |

## 能力与生命周期

| 症状 | 优先检查 | 修正方向 |
| --- | --- | --- |
| 已配置但工具不出现 | 实际挂载树、提供方、上下文分支和 pending/waiting 状态 | 检查版本对应的配置导出与激活证据，不盲目重排行 |
| 热更新后重复工具、路由或监听 | 注册是否归属于清理作用域 | 接管 disposer，验证停止和重载后的解除情况 |
| 无界面启动依赖浏览器服务而失败 | UI/HTTP 是否误列为硬依赖 | 分离必需服务与可选能力，按需动态注入 |
| 服务晚到后功能不恢复 | 是否只在启动时检查一次可选服务 | 按目标版本使用动态注入；真正硬依赖声明 inject |
| 事件后续行为消失 | 实际事件模式及 next 调用 | 按 Waterfall/链式协议调用并返回 next |
| `service "x" is not declared` | 是否未注入就直接访问 ctx.x | 硬依赖在插件返回对象上声明 inject；可选服务用 ctx.get 并处理缺失 |
| `cannot get property "timer" without inject` | 是否将 timer 当成内置全局 | 查询 timer 服务，声明 inject 后用 ctx.timeout/interval |

## 动态插件执行与版本

| 症状 | 优先检查 | 修正方向 |
| --- | --- | --- |
| 客户端代码无法解析 | 是否使用 JSX、TypeScript、import、require 或不存在的全局 | 动态函数体使用纯 JavaScript；React.createElement 通过已查询插槽注册 |
| `cordis_define` 参数校验失败 | 当前工具结构与实际提交参数 | 查询真实结构后修正，不因此切换为静态插件包 |
| 定义成功但功能未启动 | 是否只有 define，没有 run | 使用返回的确切身份调用 run；定义不会执行 apply |
| awaiting-approval 或 starting 被报告成功 | 审批与客户端异步状态 | 结束当前工具流等待平台通知，按确切 Run 的最终状态报告 |
| 用户拒绝后反复申请 | 是否误当技术错误自动重试 | 尊重拒绝，不重试、不新建插件绕过授权 |
| UI 加载后报错 | `client-render` 的确切堆栈与失败 Package | 读取原代码和诊断，在同一 Plugin 下定义修复版本 |
| host.call 失败 | 私有方法名、当前 pluginRunId、JSON 参数和宿主服务依赖 | 对齐 harness.handle/host.call 协议，不改用公共远程服务 |
| 更新失败后旧功能也消失 | current/next 指针与实际 Run | 显式对 currentPackageId 使用 run 恢复，并确认结果 |
| 修改 @pluginId 却产生重复实例 | 是否读取基准代码并使用 existing | 原实例下新增不可变 Package，保留无需修改的另一端 |
| @pluginId 已无法读取 | 已删除、另一会话、进程重启 | 如实说明失效，不能创建同名替代实例 |

## 代码模式、回放与界面

| 症状 | 优先检查 | 修正方向 |
| --- | --- | --- |
| 直接调用卡片正常，代码模式一直等待 | 嵌套调用是否经过顶层展示路径 | 检查代码分派事件，为回放/界面持久化有界业务摘要 |
| 刷新后结果消失 | 是否只存在于内存或组件状态 | 从明确的持久化事件重建；动态插件实例本身不保证跨进程存活 |
| 嵌套调用导致会话历史过大 | 是否复制完整标准值到展示事件 | 执行保留无损值，事件只保留必要摘要，不含重字段与秘密 |
| 点击详情出现空白 | 真实 owner、选择状态、键值与回退是否贯通 | 浏览器验证卡片→所有者→选择→布局→渲染器，不能只测 SSR |
| 插槽注册失败或冲突 | 当前子树、协议、键、选择器、参数及占用者 | 先查询精确插槽；不要硬编码 priority=-100 作为通用覆盖方案 |
| React Hook 错误 | 是否在条件返回后调用 Hook 或调用顺序改变 | 所有 Hook 保持无条件、稳定顺序；按实际 React 运行环境核实 |
| 新建会话没有已有会话中的选择器 | 是否只在会话创建后的入口注册 | 区分创建前默认状态与已有会话绑定状态 |
| 界面有数据却难以决策 | 是否主要展示内部字段与泛用对象查看器 | 围绕业务结果与用户操作设计内容 |
| 详情自动打开时闪烁 | 并行结果是否争抢焦点 | 汇总展示并让用户明确选择需要的详情 |
| 媒体有链接但无法播放 | 浏览器认证、跨域、签名或代理 | 检查实际媒体请求，提供浏览器可授权访问的地址 |
| 升级后 UI 入口消失 | 宿主补丁或插槽是否属于另一版本 | 核实契约与版本前提，保留可用的回退视图 |

## 插件包安装与部署

| 症状 | 优先检查 | 修正方向 |
| --- | --- | --- |
| 仓库中可用，安装后无法解析包 | 工作区提升/软链接是否掩盖缺失依赖 | 从安装位置解析依赖，在干净配置中启动验证 |
| 生产找不到源码加载器或执行旧代码 | 入口是否指向源码或错误工作目录 | 先构建，再运行发布包入口和构建后的 DSH CLI |
| 解包根目录没有 package.json | 压缩包是否多嵌套一层 | 检查实际文件清单与安装根目录 |
| 客户端声明存在但界面不可用 | 浏览器构建产物、./client 导出和模块注册 | 根据目标版本检查两端构建与包内文件，而非只看 Host 成功 |

## 推荐排查顺序

运行配置与能力图 → 认证和数据范围 → 标准结果结构 → 直接/嵌套事件 → 实际界面挂载链 → 浏览器媒体请求 → 插件包入口与依赖。动态更新问题同时对照 current/next 与具体 Run 诊断。修样式不能激活等待中的插件，重新安装也不能补回未持久化的结果。

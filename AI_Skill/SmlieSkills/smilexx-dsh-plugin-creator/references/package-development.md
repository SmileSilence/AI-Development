# 可安装插件包开发

仅用于有源码、构建与安装生命周期的 DSH 插件包。动态求值代码请使用[动态插件开发](cordis-dynamic.md)，两者不能直接复制执行环境或打包规则。

## 先核实架构与版本

读取现有 `package.json`、构建配置、Host/Client 入口、配置补丁、README 和同版本可工作的插件。确认实际 DSH 版本及运行配置；只有匹配目标版本的文档和实现才可作为接口依据。

可在实际源码路径中检索以下标识，定位工具定义、展示与打包入口：

```powershell
rg -n 'defineTool|presentationMeta|presentResult|code-dispatch|tool.details|dsh\.client|dsh\.bundle' <dsh-checkout> <plugin-root>
```

先查看目标 CLI 帮助，再使用它支持的配置导出方式；支持时可运行 `dsh --profile <profile> --dump-config`。不要把旧技能中的 `plugin.json + Python commands` 或 `dsh add/remove` 当成当前通用协议。

确认各注入服务的提供方、消费方与上下文分支；工具的标准输出结构与展示器；直接调用和 Code Mode（代码模式）的路径；回放所需持久化事件；界面插槽的所有者参数；运行依赖和上游业务范围。

## 能力图与副作用

Cordis 的 `ctx` 表示运行中会变化的能力图。`inject` 声明的硬依赖未就绪时，插件可能保持等待；配置行顺序不能证明成功激活。

- 按同版本的函数插件或服务插件导出规范实现，不混用互不兼容的导出形式。
- 路由、工具、监听器和子插件应通过生命周期 API 注册并保留 disposer（清理函数）。外部订阅通过 `ctx.effect()` 接管。
- 对可选能力使用目标版本支持的可选读取或动态注入；需要后续提供方出现时自动恢复的功能，应注册相应的动态注入作用域，不能只在启动时检查一次。
- 无界面工具不应因可选浏览器或 HTTP 服务缺失而整体失败。
- 查询事件分派模式。Waterfall（瀑布事件）和需要链式继续的钩子须按契约调用并返回 `next()`，除非明确要替换后续行为。
- 配置行保持稳定身份，以便 reconciliation（配置对账）更新原实例。验证卸载、失败激活和 HMR（热更新）后无残留或重复注册。

## 发布依赖边界

逐项分类 Host 与 Client 的导入，避免开发仓库可以运行、安装包却因重复宿主依赖或缺少运行依赖而失败。

- **插件自带依赖**：构建后仍由插件在运行时直接解析、且宿主没有承诺提供的包，放入 `dependencies` 并确认进入发布清单。
- **宿主提供能力**：DSH 核心、Cordis、Controller、Client UI 服务及宿主模块表提供的模块，不得仅因类型检查进入普通运行依赖；按目标版本契约使用 `devDependencies`、必要的 `peerDependencies` 与构建 `external`。
- **纯类型依赖**：只在 TypeScript 类型位置使用的包不得形成不必要的运行时安装副本；检查构建产物中是否仍有对应导入。
- **外置依赖**：任何被构建工具标记为 `external` 的实际运行时导入，都必须能由宿主契约或插件发布依赖稳定解析，不能依赖工作区提升、软链接或偶然存在的包。

重复安装宿主核心包可能造成服务身份不一致、导出版本错配或 Client 模块加载失败。`typecheck`、单元测试和 `npm pack` 成功均不能证明依赖边界正确；必须从最终安装 profile 解析依赖并实际启动 DSH，同时确认新增的 peer 警告不是本插件引入。

## 一个业务结果，分别提供四种表示

| 表示 | 消费方 | 要求 |
| --- | --- | --- |
| 标准 `value` | 程序与代码模式 | 满足 `output.schema` 的无损业务 JSON |
| `render` 生成的 `content` | 模型上下文 | 内容有界，保留当前任务需要的信息 |
| `presentationMeta` | 顶层调用的即时界面与回放 | 纯函数投影，独立限制大小 |
| 嵌套调用的持久化投影 | 代码模式回放与界面 | 明确写入受支持的会话事件，保留有界业务摘要 |

字段名与函数签名需要在目标版本中确认。`execute` 返回业务结果，不将界面组件或说明文本塞进标准值。展示函数不得依赖网络、时钟、随机数、进程缓存或副作用；回放不能重新执行业务操作。

用脱敏的代表性真实响应验证必填字段、可空性及输出结构。仅对自己构造的业务 JSON 做序列化；不得整体复制、枚举或序列化 Context、Service、会话快照和工具实时状态。

代码模式内的嵌套调用可能不走顶层展示路径。需要驱动界面或回放的结果，应在目标版本支持的代码分派日志入口产生有界投影；不要将完整标准值复制到所有事件中。遇到截断先判断超限的是哪一层，再决定是否需要调整通用存储机制。

## 上游接口与大结果

严格类型必须同时对齐当前服务实现、必要时的只读部署响应、产品真实的数据归属和权限范围。不要从邻近类型或 CLI 目录推测生产接口。

- 凭据复用与请求方式分开处理：可以复用已有凭据库并直接调用类型明确的 HTTP API。
- 原子工具保留过滤条件、游标和数量上限。复杂批量工作流增加高层业务工具，由其负责分页、关联、限制和缺口说明。
- 精确聚合尽量靠近权威数据与租户过滤执行；汇总值不能随展示页切换而变化。
- 只对明确的兼容性信号回退，例如接口确实不存在；鉴权、输入和服务器故障必须传播，不能伪装成空结果。
- 用户先决定意图和约束；工具完成数据工作，界面呈现业务结果。修改数据或发布等操作按实际授权区分预览与执行。

## 界面与回放

围绕用户下一步需要做的决定设计卡片和详情：说明结果、范围和异常；仅调试时展示内部工具名、ID 和 JSON。大量数据使用服务端分页/搜索与有界 DOM；媒体链接必须能在浏览器授权环境实际访问。

对带键值的详情插槽，验证整个挂载链：卡片点击 → 实际 ToolCall 所有者 → 选择/openDetails → 共享详情布局 → 对应渲染器 → 有内容的业务视图或回退视图。SSR（服务端渲染）或孤立组件测试不能替代这一检查。

多个结果并行完成时不要争抢自动打开详情的焦点。会话创建前的默认设置与既有会话绑定状态应放在各自生命周期对应的界面入口。

对本次涉及的行为验证：直接调用、代码模式嵌套调用、完成后的刷新与回放、卸载重载、失败与中断。持久化摘要不得带凭据，也不能依赖原始网络响应或组件内存。

React 接入外部状态时要验证方法的接收者绑定。向 `useSyncExternalStore` 等 Hook 传递对象方法时，优先使用 `() => scope.getSnapshot()`、`(listener) => scope.subscribe(listener)` 这类闭包；直接传递 `scope.getSnapshot` 或 `scope.subscribe` 可能丢失 `this`，表现为页签存在但内容为空。验收必须同时检查页签内容、交互和浏览器控制台，不能只确认页签标题出现。

## 构建、打包与独立安装检查

按项目已有工具执行构建和打包，不假定技能提供额外检查脚本。

1. 增加命名契约检查：核对 `package.json.name`、Cordis 实例 ID、Host 插件名、设置命名空间、插槽条目 ID 和样式前缀；SmileXX 自有插件全部以完整 `smilexx-<plugin-name>` 隔离。
2. 检查 Host 的 `main` / `exports` 指向发布包实际包含的 Node 构建产物，而非源码加载器。
3. 如声明 `dsh.client`，检查 `./client` 对应的浏览器构建产物、模块注册与 UI 依赖符合目标版本。
4. 检查 `dsh.bundle` 及配置补丁在预期分支挂载 Host 插件；安装后导出配置确认实际树，而非只确认文件存在。
5. 查看 `npm pack --dry-run` 与 tgz 内容；确认 `package.json`、入口、客户端代码、补丁和运行时资源都在正确位置，并比对已安装构建产物与最终源码构建的哈希。
6. 从安装目录解析运行依赖及 peer dependencies（宿主提供的依赖），防止单仓库提升或软链接掩盖缺失依赖；执行运行依赖审计时区分生产依赖与仅开发依赖告警。
7. 把最终打包产物安装到隔离的临时配置，使用构建后的 DSH CLI 启动，确保源码仓库的 `node_modules` 不参与解析。
8. 在该配置验证挂载、一次代表性调用、卸载和再次启动；有客户端时验证浏览器交互、控制台及亮暗主题。独立测试结束后清理本次临时配置。
9. 插件或实例改名时按 SemVer 升级处理：卸载旧包，迁移或删除且仅删除本插件拥有的旧设置，导出配置确认旧 ID 为零、新 ID 唯一，再安装最终 tgz 并确认 profile 指向该产物。
10. 卸载验证所有插槽、订阅、锁、频道、样式和活动对象均消失；重新安装最终构建包后再次启动，避免验收停留在临时或旧制品上。

仅在涉及部署时继续验证反向代理、认证边界、持久化 DSH 主目录与进程重启。交付中记录实际版本、构建与安装命令、通过的运行模式和未满足的宿主条件。
